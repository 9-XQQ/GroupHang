# 隔离浏览器验收

真实前端连接随机PostgreSQL schema，不使用已有账号和行程。本脚本用于本机交互验收；前端状态自动回归由unittest调用Node执行，不等于浏览器CI。

## 启动

在项目根目录和route_plan环境执行：

    $env:AGENT_DB_TESTS = '1'
    python -m tests.browser_acceptance_server --state-file docs_private/browser-state.json --stop-file docs_private/browser-stop --ttl 2700

启动前确保本次stop文件尚不存在；不要覆盖另一轮正在运行的state文件。docs_private目录需存在。服务绑定127.0.0.2随机端口，与127.0.0.1开发服务隔离Cookie。state文件含端口、测试用户名和随机短期密码，只用于本次测试，不提交。

地图/模型/SMS密钥在子进程内关闭，不编辑.env。POI搜索为测试替身，道路调用返回明确估算原因。静态页和业务API使用真实实现，WebSocket数据库工厂绑定同一schema。

## 核验顺序

1. 登录：刷新后保留登录，不自动进入旧行程；偏好保存并回填。
2. 创建行程、保存起点/时间，立即从收藏加入地点，不出现版本过期。
3. 确认两处必去地点、生成路线，查看估算声明。
4. 第二账号通过邀请码加入；看不到前一账号私人收藏/备注，可读取同行评论，无创建者状态控制。
5. 成员生成路线使用创建者已保存参数，两人赴约段正确显示。
6. 吃饭/品牌/半日游均有推荐、原因与估算说明，相同收藏/在线POI不重复。
7. 同账号两页打开同一行程，一页保留未保存起点，另一页提交后前者输入不被覆盖。
8. 半日游选择返回中心后接入正式路线：先取消、再确认，核对地点/时间/返程及查看路线步骤。
9. 页面内最终确认显示实际顺序；含估算段时未勾选不得提交，Escape取消后重开必须重新勾选；确认后重新编辑、生成/再确认、标记完成。
10. 刷新重开已完成行程，规划输入与添加地点禁用，收藏/同行评论/评价仍可用；保存评价后重新打开核对持久化。
11. 改密涉及新凭证输入时遵循工具约束，不能以HTTP测试冒充浏览器验收。

## 停止与清理

从另一终端创建本次指定stop文件。正常退出时删除本次确切随机schema，state变为cleaned并移除测试密码；TTL到期也清理。不要重置数据库或删除已有schema。强制终止可能无法执行finally，应仅核查本次state中的schema，禁止批量删除前缀匹配项。

自动回归：

    python -m unittest tests.test_frontend_state -v
    $env:AGENT_DB_TESTS = '1'
    python -m unittest discover -s tests -q
