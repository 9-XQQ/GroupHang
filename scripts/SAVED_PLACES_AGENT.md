# 收藏地点、同行评论与三种Agent推荐

当前为本机开发功能，迁移head为0014_trip_return。没有部署或调用真实付费服务进行验收。

## 收藏与评论

登录后从侧栏进入“收藏地点”，按城市搜索地点、从现有行程地点卡片收藏，或填写/使用地图坐标新增。可编辑多个标签、建议停留时间与最多2000字的私人备注/评价/回忆；支持按标签筛选和翻页。重复收藏同一POI或同名同坐标地点返回原收藏，不覆盖已有私人备注。

收藏仅本人可读写。加入行程时复制规划字段，私人备注和标签不公开；取消收藏不会删除行程中的地点。收藏修改有revision校验，旧页面需刷新。收藏加入当前行程会新增候选，仍由创建者确认“必去/可选”。

行程地点卡片的“同行评论”是独立功能，仅本行程成员可见，作者可编辑/删除自己的评论。评论不修改路线版本，已确认/完成行程仍可交流；原已完成地点评价的私人评论保持原语义，不会自动公开。

## 侧栏与使用前提

侧栏为“我的行程、收藏地点、共同约点、路线规划、行程助手”。收藏无需打开行程。三种Agent推荐使用当前行程的参与者起点和交通方式，因此需先打开/创建行程，各成员提交自己的出发设置。

切换导航仅切换视图，不自动改变Trip主方案；原“选择规划方式”按钮仍是创建者修改主方案的入口。切换账号会清空收藏/推荐/评论缓存，刷新不会自动打开旧Trip。

参与者可以勾选“允许本行程推荐使用我的主动旅游偏好”。默认关闭；当前提问者也可在推荐条件中关闭使用偏好。只使用主动结构化类别，不读取其他成员收藏备注。多人吃饭的排序先按最远一人赴约耗时的5分钟组比较，同组偏好匹配优先，再比较精确耗时与总耗时。

## 三种场景

在“行程助手”选择场景，或让对话自动识别，填写条件后询问：

1. 多人吃饭：“我们约着吃饭，不知道去哪，推荐几家餐厅。” 比较各自赴约耗时，返回最多3个候选；使用符合条件的个人收藏和附近餐饮POI。
2. 品牌分店：“决定吃寿司郎，比较几家分店。” 明确城市和品牌，展示逐人交通、商场/周边公园证据以及已授权偏好匹配。无可靠信息时明确清净、排队和营业未知。
3. 区域半日游：“在人民公园附近玩一下午，2026-11-01 13:00～17:00。” 可以用地图选点作为中心，设置半径、时间、默认停留、收藏标签及只使用收藏。勾选返回中心会计入返程时间。缺少精确时段或锚点时要求补充；同名锚点需消歧。

半日游返回时间线、推荐地图标记、共同路段、未选择原因和真实/估算状态；不会编造地点。LLM仅可辅助抽取意图/品牌/锚点，不接收私人备注、成员起点或偏好，不生成路线事实。三场景均可在未配置LLM时使用明确场景及条件。

推荐预览不修改行程。勾选地点后“确认加入选中地点”，原子写入候选地点，版本变化会使旧推荐失效；收藏revision变化也会拒绝。重复提交同一批来源不重复加入。默认“确认加入选中地点”仍只加入候选。对半日游推荐，发起人还可选择“保存所选地点及时段，生成新路线”：显式确认后，原子保存所选地点为必去和推荐时段，保留原有必去/可选地点，再使用全部当前输入重算正式路线。顺序/耗时可能与预览不同，最终确认独立进行。计算失败保留已保存输入，可在路线规划重试。主方案须已切换为多地点路线。勾选返回中心时，返程终点会一起保存并参与正式路线计算。

## 计算边界

- 范围为明确中心的地理半径（默认5km，可改0～20km内正值），不是道路绕行预算；品牌搜索限明确城市。
- 每次最多读取最近100个符合筛选的收藏，评估8个候选；餐饮/分店最多3个推荐，半日游最多5站，参与者1～10人；不是全局最优保证。
- 时间预算包含个人赴约、成员等待、共同交通和停留；半日游与正式路线均可含返回中心，不等于每个人返回自己家的完整返程。
- 半日游只规划本次候选，未合并原行程全部地点和固定时间窗；不要把预览当作原Trip最终方案。
- 高德不可用时只使用可用收藏，路线可降级估算并明确标注，不能作为导航或严格准时承诺。候选搜索无结果时不会虚构餐厅。
- 工具计算总期限75秒，超时提示缩小范围重试。最终HTTPS、云端部署及多worker广播不在本轮范围。

## API

- GET/POST /users/me/saved-places，PUT/DELETE /users/me/saved-places/{id}
- GET/POST /trips/{id}/destinations/{destination_id}/comments，PUT/DELETE .../{comment_id}
- POST /trips/{id}/places/import：expected_version和1～10个places；收藏使用saved_place_id/revision，确认的POI使用place对象。发起人准备路线时，须同时传confirm_for_planning=true和完整planning_settings。
- POST /trips/{id}/assistant/discover：scenario=meal/brand/afternoon及结构化条件。
- POST /trips/{id}/assistant/chat：保留原聊天；discovery可附加结构化条件，推荐场景返回discovery结果，原草案执行机制保持不变。

## 共同返程（0014）

路线规划新增“共同返程终点”：可使用地图选点或填写坐标，保存后刷新回填。正式路线把末站到终点计入交通/总时长/距离与可选点预算，显示返回时间和路线；终点也是路线快照的一部分，后来修改Trip参数不会改变旧快照。取消勾选并保存可清除终点，旧路线随版本失效。旧API请求省略return_location时保留原值，显式null才清除。

Agent路线比较和生成也使用已保存的返程终点，半日游准备路线入口可保存返回中心条件。估算返程同样要求最终确认时明确接受估算。超出行程或成员结束时间会产生警告；现有规划并非严格可行性保证，不因增加返程就承诺准点。共同终点不包含提前离队或各自返家。
