# 账号密码登录

当前页面默认使用用户名和密码，不需要手机号、短信资质或外部服务。短信适配器保留备用，实际 .env 不改动，真实短信发送保持原关闭状态。

## 使用

迁移至 `0012_password_auth`，然后重启 Web 服务。页面“注册新账号”可注册并登录；已有用户名选择“登录”。用户名3～32位字母、数字或下划线，忽略大小写；新密码8～15个字符，允许中文、空格，大小写及空格严格保留。昵称选填，默认用户名。

登录后点击顶部昵称进入“我的账户”，可查看用户名、修改昵称、设置旅游偏好，展开“修改密码”输入当前密码与新密码。修改后撤销所有旧会话，给当前客户端签发新会话；其他设备需重新登录，当前页面会重建WebSocket以使用新会话。普通登录仍允许多设备同时在线。刷新只恢复身份，不自动打开旧 Trip 或地图选点。

## 旧账号和忘记密码

已有手机号用户、Trip、偏好及成员关系保持原状。注册新用户名会创建独立账号，不会按未验证手机号关联原账号。

本机管理员核实账号归属及用户ID后，在交互终端运行：

```powershell
python scripts/set_account_password.py --user-id 123 --username your_account
```

123只是示例，必须替换为准确的既有用户ID。工具交互隐藏输入两次密码，不接受命令行密码或管道输入；绑定后撤销该用户所有旧会话。已有用户名只允许使用原用户名重置，不会自动改名、合并账号或覆盖其他用户的用户名。

本轮未运行任何实际用户的绑定/重置。没有默认账号或默认密码，也没有公开的免验证找回接口。暂由可信管理员重置；上线公网前再确定邮箱验证、自助找回和账户恢复流程。

## 安全和接口

- scrypt（N=32768,r=8,p=3），每次随机16字节盐，只存不可逆哈希；两个专用线程处理哈希，避免阻塞请求事件循环。
- 登录账号每15分钟最多10次、来源IP每15分钟30次，注册每IP每小时5次；修改密码同样限流。所有请求包括成功请求都会计数；原子 upsert 在数据库中共享额度，错误响应不会回滚计数。超过配额返回429和Retry-After；限流记录一天后清理。
- 不存在账号与密码错误返回相同401消息，并对未知账号执行同成本哈希校验。认证参数错误不回显密码；认证异常不输出开发 traceback。
- Cookie沿用HttpOnly、SameSite及生产Secure约束，状态修改验证自定义请求头和Origin，默认仅同源CORS。部署公网必须使用HTTPS，并正确配置可信代理；请求IP以Uvicorn处理后的可信来源为准。
- 登录和改密最后锁用户并重新检查密码摘要，避免管理员重置/并发改密后仍用旧密码建立会话。
- `POST /auth/register`：username,password,可选name,browser。
- `POST /auth/password/login`：username,password,browser。
- `POST /auth/password/change`：current_password,new_password,browser（必须登录）。
- 浏览器browser=true接收Cookie；API默认返回token，后续使用X-Token。密码修改API客户端需使用返回的新token。
- `/auth/me` 和 `/auth/logout` 保持原会话机制。原短信登录API保留，页面不再展示短信登录。

## 登录会话管理

用户已确认账户入口、昵称、旅游偏好和8～15位密码的页面验收完成。新增登录安全区域显示当前有效会话数，支持退出其他会话并保留发起请求的当前会话；操作前页面二次确认。会话数不等于设备数，不采集设备指纹或展示token/hash。已过期或撤销的会话不计入数量。

GET /users/me/sessions 返回active_sessions；POST /users/me/sessions/revoke-others返回revoked_sessions，仅操作本人，Cookie写操作要求校验头和可信Origin。重复执行返回0；其他会话下次请求失效，WebSocket按既有定期检查最长约10秒关闭。撤销期间之后新建立的登录仍被允许；该功能不是单设备登录策略，也不防止知道密码的人重新登录。
